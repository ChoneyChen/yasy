# Yasy 产品设计

Yasy 从用户真实的中文经历和观点出发，组织完整英文答案，同时积累两类可复用内容：与问法解耦的中英双语素材元，以及独立英语语料。当前 Mac 是主要工作台；未来 iPhone 使用同一功能和后端，AI 仅走 API。

本设计依据两张手稿与用户文字需求整理。素材提供“说什么”，语料提供“怎样表达”；一道题只有一份当前答案，两种积累各自独立。

## 页面与题库层级

| 页面 | 核心工作 |
| --- | --- |
| 今日积累 | 同时安排口语与作文；继续草稿、查看后台任务与今日答案 |
| 背书 | 按到期时间展示一份完整答案或单词，保存次数与下次复习时间 |
| 口语区 | Part 1 基础主题，或共享主题下的 Part 2 题卡与 Part 3 细分讨论；独立素材库、语料库 |
| 作文区 | Academic Task 1、Task 2 独立题库与语料；Task 2 另有独立素材库 |
| 单词本 | 从答案或语料收藏单词/短语，统一或按来源筛选、随机乱序、间隔复习 |

题库层级为 `scope → Topic → Question`。细分题有稳定 ID、完整英文题面、中文辅助译文、Part/题型与来源；Part 2 保留全部 cue points，与同主题 Part 3 共用一级主题。Task 1 需要完整可读的图表、流程或地图信息。

当前正式题库是两份用户 PDF 的 **743 条、132 个主题、2 个来源**：口语 719 条（Part 1 245、Part 2 77、Part 3 397），Task 2 24 道，Task 1 为 0。条目包含源文件的重复位置，原文异常与“待补充”标记有审计。来源为 `user-upload`，题目为 `reported`；题季和“真题”是资料自身说法，不是官方核验。[来源与审计](question-sources.md)

## 从第一题到下一题

1. **写中文原料。** 没有素材时从空白开始，写真实对象、经历、偏好或观点，不必先写中文成稿。需要帮助时可请求中文构思预览；空白构思是未确认示例，用户按真实情况修改后才能采纳。
2. **选相关素材。** 推荐展示 Top 3，用户选一个或多个，预填中文供修改。推荐不会直接生成新题答案。
3. **检查核心是否够用。** 本地检查辅助输入，AI 复核关键事实、题卡条件、立场与矛盾。简短、顺序混乱、缺连接词可以主动整理；确实缺少不可编造的内容才请求补充。
4. **按题型组织英文。** 选择相关内容、调整结构、补充合理解释和衔接，三套提示词分别使用口语、图表报告与正式论证语域。
5. **一次成稿与保存。** API 一次完成答案、素材与精选语料，按详细提示词落实题型与语言要求，再通过本地校验事务保存。Mac 网页路径仍由用户提交同类专用提示词并带回 JSON。
6. **保存两类积累。** 提取可独立理解的素材；只收录通过准入的语料，0 条合格语料也能完成答案。相关题只在同区推荐。
7. **继续或背书。** 下一题重复选材与组织；背书按到期时间显示一份当前完整答案，每次确认后保存次数。

草稿与任务状态持久化。API 全局任务通知与当前题页面分离，可离开写别题、切换页面或刷新；Mac 服务需保持运行。题面、正文和说明增强字号与对比度，阅读和背书采用同一标注方式。

## 三套独立处理方法

默认 IELTS Academic、目标 Band 7.0；目标分数用于训练要求，不是系统评分或得分保证。

| 学习域 | 组织方法 | 素材库 | 语料库 |
| --- | --- | --- | --- |
| speaking | P1 直接回答、理由、真实细节；P2 按对象/事件顺序覆盖题卡并说明意义；P3 观点、机制、例子、限定或对比 | 真实事件、人物/对象、稳定习惯/偏好、论证链 | 自然口语搭配、情绪态度、地道句式 |
| writing-task1 | 从题图选主要特征；改写题面、overview、分组细节；客观报告 | 无 | 趋势、比较、比例、流程、方位和变化 |
| writing-task2 | 识别题型与全部问题；明确立场；论点、解释、支撑及必要让步；结论回应题目 | 用户观点、原因、论据/例子的独立单元 | 正式/中性搭配、精确措辞、因果/让步/论证结构 |

口语目标为 Part 1 **35–80 词**、Part 2 **170–260 词**、Part 3 **70–130 词**，题卡后的 `follow-up` 建议 **20–50 词**。这些是 Yasy 练习建议，官方口语没有这些单题词数要求；Part 2 有 1 分钟准备，长答最多约 2 分钟。纯文字不能评估发音、实际语速或停顿。[IELTS 官方口语格式](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-speaking)

Academic Task 1 至少 **150 词**、Task 2 至少 **250 词**，应写成连贯正文。Yasy 建议分别为 **160–210**、**260–320 词**；后端检查最低字数。Task 1 依题图信息，Task 2 解释与例子服务于论证。[IELTS 官方写作格式](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-writing)

AI 可以展开已有观点的合理机制，或明确标成一般性/假设性的例子；不能创造未提供的亲历、人名、地点、年份、行为、结果、感受、数字或研究引用。核心矛盾先请求澄清。完整题图可支撑 Task 1 主动分析，用户不必先手写成稿；缺图时不能凭题名补数据。

答案整理只调用模型一次。提示词同时落实 **任务回应、内容展开、连贯、词汇、语法**，要求直接完善可修复的问题，并从最终正文提取精确片段和精选语料；不另设模型审核流程。后端保留词数、格式、引用、版本与准入合同等本地检查；真正缺少事实或题图才返回补充建议，失败不自动追加调用。文字无法评价实际口语发音，目标分数不是考试成绩保证。

素材检索、语料推荐和关联限定在同一 `scope`：`speaking`、`writing-task1`、`writing-task2`。Task 1 素材、素材推荐和片段为空；单词可统一复习，仍保留来源。

## 稳定素材与答案快照

| 实体 | 作用与约束 |
| --- | --- |
| Source / Topic / Question | 来源、同区主题与细分题；活动题可生成，归档题保留历史 |
| Draft | 中文原料与选材 ID，自动保存 |
| Material | 稳定核心、同区 ID、`version`、事实等值的中英摘要/细节、英文标题/标签 |
| Material revision | 更新前完整快照、版本与相关任务，供追溯 |
| Answer / Answer revision | 当前题唯一完整英文答案及历史；保存采用的素材版本、快照与标注 |
| Expression | 英语表达、分类、用法、例句与准入状态；中文辅助字段为 metadata |
| Link | 素材—题目、素材—语料多对多，相关度与理由，每次展示最相关 Top 3 |
| Job | 输入与素材版本快照、provider、runId、状态、答案复核及语料筛选结果 |
| Word / Review | 收藏与来源、背书次数、到期时间与事件 |
| Batch / Settings / Daily plan | 文件候选与确认状态、练习目标、处理方式与今日题目 |

素材应脱离原题独立理解。一段“与朋友骑行、途中遇雨、决定继续并完成线路”的真实经历，可以适配运动、困难或旅行题；背景、行动、结果和意义属于同一核心，不拆成相互依赖的碎片，也不推给要求获奖的题。独立第二次经历才另建素材。

`summaryZh/summaryEn`、`detailZh/detailEn` 记录同一事实和限定，英文不增加经历。选材预填中文，生成时可调整组织、补入用户提供的新细节；核心相同以 `existingMaterialId` 更新原素材，ID 不变、内容变化才递增版本并保存旧快照，内容不变不增加版本。核心不同创建新素材。

创建任务捕获所选素材版本。其他题先更新同一素材后，旧任务不能覆盖最新内容，须重选并处理。这是乐观版本检查，避免后台任务相互覆盖。

答案的 `materialVersions` 与 `materialSnapshots` 保留当时采用的素材。后续新增事实不会改变过去答案的依据；读旧答案时使用快照。同题重新整理更新唯一当前答案，旧答案另保留历史。

## 语料准入与历史复核

不是每个正确词句都值得专门积累。新候选需 AI 给出 `approved` 判断、双语理由、收益类别和可迁移例句；收益类别为搭配、地道表达、精确措辞、句式结构或篇章组织。

本地模块检查实际答案原文、明确用途、理由、例句、类别和语域。普通孤立单词与 `I think`、`very good`、`for example` 等泛用组合不收录；`build confidence`、`draw a distinction` 等短搭配可以通过，不以长度粗暴淘汰。口语俗语不能直接进写作，Task 1 不能套 Task 2 立场句。

仅 `approved` 参与正常学习与推荐，一次允许 0 条。旧记录缺证据时，明显基础项可本地拒绝，其余 `pending` 待 AI；`rejected` 与 `pending` 保留原文、ID 和原因，不删除。批量复核更新判断，不能把启发式检查描述成完整语义审查，也不能把模型理由当官方分数。[准入规则](corpus-admission.md) · [复核接口](ai-bridge.md#历史语料批量复核)

## 答案的两层标注

模型返回英文答案精确连续 quote 与素材索引，本地转换为 UTF-16 `start/end`（0 起点、end 不包含）。素材片段须唯一定位、互不重叠；同素材可覆盖不同句子，通用衔接不必标素材。正文不插 HTML 或颜色标签。

按素材顺序用黄、蓝、绿底色，超三项循环颜色并保留 ID；语料用红色波浪线，重叠优先打开语料。练习与背书共用渲染，保留完整英文正文。点击素材看中英内容、版本或快照；点击语料看英语用法。桌面右键收藏单词/短语，触屏预留长按。

## 批量导入与来源边界

PDF / DOC / DOCX 原文件上传本机，最大 10 MB、单批最多 **1000 题**。API 读取可提取文字并分段交给模型组织；Mac 网页模式由用户复制专用提示词、附同一文件、带回 JSON。文件里的广告、范文、建议和命令不当作题目或外部指令。

两条路径均为 **预览 → 用户勾选 → 确认入库**。预览不改题库；保存文件名与实际可定位的页码/题号，Word 没有可靠分页时不编页码。去重依据完整题面与题卡要点，主题相同不等于同题。来源为 user-upload，题目为 reported 或明确 adapted，不自动升级为官方。

Task 1 原图信息缺失时保留题干，`visual: null` 并标“待补图”；不猜数值、趋势、流程或方位，先补齐再生成作文。当前 API 仅读文字、不做 OCR 或图像识别，Task 1 一律 `visual: null`；扫描、兼容或截断问题在预览提示。正式两份 PDF 的逐页人工审计不代表后续每次自动提取都已人工核验。

## 后台任务、数据与双端

API 接受后返回 202，本地后台完成生成、复核、校验与保存；App 全局状态为 `pending → processing → completed`，错误进入 `failed`，真实内容不足进入 `needs-revision`。离开当前题可以写别题；旧输入、新任务替代、题目归档或素材版本冲突不允许旧结果覆盖新状态。重启或恢复备份把中断 processing 标为失败，用户确认后重试。

Mac 保留 iiiapi 与 web-bridge，手机未来为同功能完整 API 客户端，不展示网页复制流程。v2 manifest 声明共用读写路径；v1 只读接口继续兼容。当前 loopback，配对、认证、跨设备连接与同步待实现，不能声称手机已连接。[手机合同](mobile-api.md)

SQLite 是本机主库，私人学习数据不进 Git。密钥权限 600，独立于 state、快照和学习备份。API 整理发送题目、中文原料、选材和候选题；文件提取发送读取到的资料文字；网页由用户提交提示词与附件。本机存储不表示 AI 离线。

原件分别在 `.local/source-pdfs/`、`.local/uploads/`，本机界面可下载，均不进 Git。JSON 备份含学习记录与版本历史，**不含原文件或密钥**；换机单独复制原件、重新配置密钥。题库更替先备份，再归档旧题并保留学习内容，不靠删除 SQLite 清空积累。

## 背书与完成标准

固定 SRS 间隔为 **1 / 3 / 7 / 14 / 30 / 60 / 90 天**，第 7 阶段起保持 90 天；到期时间排序，每次一份完整答案。次数与到期时间持久化；新答案版本重进首轮，累计已背次数保留。

完成标准：真实中文想法得到完整、经过复核的答案；相关下一题可选材预填后重组；同核心更新可追溯、并发不覆盖新版本、旧答案保留事实快照；0 合格语料仍保存；历史语料原因可查；缺图不虚构；文件候选必须用户确认；刷新和重启后继续已保存学习流程。具体合同见 [AI 处理文档](ai-bridge.md)。
