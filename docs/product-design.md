# Yasy 产品设计

Yasy 是先在 Mac 本机使用的雅思学习工作台。核心是两条并行积累线：用户真实的中文素材，经过整理成为可复用的中英双语素材元；同一份回答里的好词句，成为独立语料。题目答案是两条线在当前题目上的一次组合。学习界面使用英语，中文保留在输入、材料对照和辅助解释中。iPhone 先保留阅读、复习和同步的设计边界，主要写素材和 AI 处理仍在 Mac 完成。

本设计根据两张手稿及用户文字需求整理。手稿的“素材核心事件”“与问法解耦”“词句与素材互补”“单词本”和大小作文分类都落在独立实体与流程上。

## 页面与题库层级

| 页面 | 核心工作 |
| --- | --- |
| 今日任务 | 同时安排口语与写作；继续未完成的中文草稿、待导入任务、今日新题与已完成答案 |
| 口语区 | 浏览全部口语主题，进入 Part 1 基础问答、Part 2 题卡和 Part 3 延伸问题；查看本区素材库与语料库 |
| 作文区 | Task 1 与 Task 2 独立题库和语料；Task 2 另有独立素材库 |
| 单词本 | 从口语或作文答案、语料中保存单词/短语，支持统一查看、按来源筛选和随机乱序复习 |

题库层级为 `scope → 主题 → 细分题`。每个细分题有独立 ID、完整题面、中文提示、Part/题型和来源。口语题卡保留 cue points；Task 1 保留图表、表格或流程/地图信息，不把只有题干的残缺题目当作可生成作文的完整输入。官方公开样题、考生回忆题和根据来源改写的练习题分别标注来源类型，保留链接、检索日期及已知的题季/回忆日期；不把回忆题宣称为官方发布的全量当季真题。

用户还可以把自己的题库文件接入同一题库：在本地创建文件导入任务，复制文件提取提示词，在 ChatGPT 网页手动上传该文件并取得 JSON，再导回 Yasy。本机这一阶段不自行提取文件正文。批次按文件真实内容拆分主题、Part 和细分题，最多 500 题，来源保存为 user-upload，每题保留文件名、页码/题号与原题或改写的说明。来源文件缺失 Task 1 原图时，题干可先入库但 visual=null、来源说明标记需要补图；在图表信息补齐前不能据此生成完整作文。文件名写着“当季真题”不等于系统验证了当季真实性。

## 从第一题到下一题

1. 用户进入一道题。没有既有草稿或推荐素材时，中文框为空；先写自己的经历、细节、理由或观点。
2. 若系统有推荐，展示相关度最高的 3 个素材及推荐理由。用户选择一个或多个后，将真实中文细节预填写到草稿框；用户可以修改、删除、补充。推荐本身不等于适合新题的完整答案。
3. 用户提交中文材料，系统先作本地启发式初检，提示空白、过于简略和关键细节缺口。初检不是雅思评分，也不宣称完成了事实、偏题或论证的完整审查；未通过时提供补充方向，保留草稿供重写。
4. 初检通过后，创建绑定题目和当前输入的 AI 任务。系统生成该 scope 的专用提示词，提供复制、打开 ChatGPT、粘贴结果导入的网页桥。
5. 网页 AI 必须再次检查内容是否能回答题目。二检不通过只返回中文补充建议，答案和积累数组为空；用户重写后建立新的处理任务。
6. 二检通过后生成本题的一个英文答案、中文结构、独立双语素材元、答案中各素材所对应的真实片段、好词句，以及同区候选题的素材推荐。
7. 导入时先验证结构、任务/题目绑定、scope 和引用。验证通过后保存当前唯一答案，把素材与语料分别入库，建立同区的多对多关系。用户可在答案中看到素材颜色和词句高光，并加入单词本；素材可以中英对照，语料的分类与用法提示可直接以英语显示。
8. 完成一道题后进入下一题。如果下一题收到素材推荐，重复“选择→中文预填→修改→初检→AI 二检→整理”的流程；没有推荐则从空白真实中文内容开始。

在任意时点，中断的中文草稿都应能找回。推荐只预填中文，不将旧答案直接搬到新题，不替用户虚构缺失事实，也不会在用户尚未选择时给目标题写入正式答案。

## 数据实体与约束

| 实体 | 内容与关系 |
| --- | --- |
| Source | 官方/回忆/改编题的原始来源、链接与检索信息；用户文件另标记 user-upload 并保存文件溯源 |
| Topic | 一组同 scope 的主题，包含多个 Question |
| Question | 最小练习单元；属于一个主题，关联至多一个当前 Answer |
| Draft | 本题中文内容与用户选中的素材 ID，可在生成前继续编辑 |
| Answer | 当前题唯一英文答案、中文结构、词数、素材/表达引用、素材颜色片段及生成任务 ID |
| Material | 独立核心事实或观点单元；summaryZh/summaryEn 与 detailZh/detailEn 是事实等值的双语对照，另有标签和 scope |
| Expression | 好词句、中文意义、中文/英文分类、中文/英文用法边界、英文例句、标签和 scope |
| Link | 素材—题目、素材—表达的多对多关系，附相关度与理由 |
| Word | 用户选取的单词/短语及来源 scope/题目，支持合并复习与来源筛选 |
| Job | 某次输入快照、提示词、所属题目和处理状态，使导入结果可校验 |
| Daily plan / Settings | 今日题目安排、口语/写作量、目标练习难度和 AI provider |

题目和当前答案是一对一：重新整理更新当前答案，不让同一题出现多个并列“最终版本”。生成任务可以保留过程记录，但任务记录不改变当前答案唯一性。素材—题目和素材—语料都是多对多；页面每次展示最相关的前 3 个，弱关联不为了凑数展示。

一个素材元应能脱离原题独立理解。例如用户写“去年和朋友在杭州骑车，开始怕下雨，后来决定继续，终于完成了线路”。可以保存核心经历、具体行动及结果，再分别适配运动、克服困难或愉快旅行题；不能将“去年”“下雨”“完成”切成互相依赖的三个碎片，也不能推送到要求“获得奖项”的题。独立的第二个事件应成为另一个素材元。

每个素材保留中英二元组：中文记录用户真实事实，英文用本区语域表达同一组事实。时间、人物、行动、原因、结果、假设性和限定要逐项等值；英文不能替用户添加经历。素材 title 使用简短英文，中文含义通过 summaryZh/detailZh 对照，不新增 titleZh。口语素材的英语适合说出来，大作文素材的英语适合正式论证，两者仍严格分库。语料区显示英文类别、英文用法和英文例句，原有中文辅助字段只保留为 metadata。

答案的素材颜色与语料高光是两层信息。AI 输出当前英文答案中完整且连续的原文 quote 和对应素材索引，本地校验并找到其字符范围，再保存 JavaScript UTF-16 的 start/end（从 0 开始、end 不包含）。每一片段只属于一个素材，不重叠；同一素材可覆盖不同句子，通用衔接句可以没有素材标签。界面优先使用三种素材颜色；超过三个真实独立素材时可以重复颜色，不能为配色把素材强行合并。语料仍标出答案里实际出现的好词句，颜色不改变英文原文。

语料关注语言功能，如表达担忧、转折、因果或趋势，不是同一事件的英文摘要。`textEn` 必须出现在当前答案中，才能准确高光。素材与语料通过关系联结，双方都能独立检索和复习。

## 三个严格独立的学习域

| scope | 素材库 | 语料库 | 答案约束 |
| --- | --- | --- | --- |
| speaking | 真实经历、人物/习惯/偏好、用户自己的观点与理由 | 地道口语搭配、情绪态度、常用句式 | 根据 Part 1/2/3 调整结构，优先自然可说 |
| writing-task1 | 无素材元 | 趋势、比较、比例、流程、地图空间描述 | Academic 客观信息报告，含 overview，不虚构题图信息 |
| writing-task2 | 用户观点—原因—论据/例子的独立论证单元 | 正式搭配、因果、让步、论证、谨慎限定句式 | 按具体题型回答全部问题，立场一致，有展开论证 |

素材检索、相关题推荐及素材—语料关系必须限定同一个 scope。Task 1 没有素材推送，所有素材引用为空。单词本可以跨来源统一复习，但保留来源；统一复习不等于合并口语与写作语料库。

口语 Part 1 的 20—60 词、Part 2 主题卡的 180—280 词和 Part 3 的 60—110 词是本产品的练习建议，实际应按题目与语速调整。Part 2 题卡后的简短收尾追问标为 taskType=follow-up，按简答练习（建议 20—60 词），不重复长题卡故事。官方口语规则按对话阶段与时间描述：Part 2 准备 1 分钟并持续讲述 1—2 分钟。[IELTS Speaking 格式](https://www.ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-speaking)

Academic Task 1 至少 150 词，Task 2 至少 250 词；Yasy 的训练长度建议分别为 160—210 和 260—320 词。小作文依据图表概括主要信息，大作文发展观点并给出理由/例子，完整连贯的句子是正式答案格式。[IELTS Academic Writing 格式](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-writing)

## Mac 本机架构与 iPhone 预留

浏览器界面负责学习工作流，本地服务负责数据、校验、推荐和 AI 任务；SQLite 是本机持久化主存储。默认服务仅监听 loopback。浏览器刷新或关闭后，草稿、答案、素材、语料和单词仍留在 Mac；题库数据和程序代码与私人学习数据分开，私人数据不进入 Git 仓库。

AI 处理经过 provider 层，网页桥和未来 API provider 使用同一结果合同，前端不绑定某个网页 DOM 或某个模型。首版 provider 的状态如实标注为半自动：提示词生成和结果入库自动完成，用户在 ChatGPT 网页提交提示词并复制 JSON 回来。具体接口与导入校验见 [AI 网页桥设计](ai-bridge.md)。

iPhone 可在后续以适配移动屏幕的网页/PWA 为阅读与复习入口，沿用稳定 ID、scope、题目和答案实体。手机接口先预留只读的 version 1 合同，服务仍仅本机监听，不开启局域网或外网连接。跨设备访问需另行实现配对认证、连接方式、同步与冲突策略；首版本机监听不意味着手机已经可访问。素材书写与生成任务先以 Mac 为权威入口。未来同步可以通过导出/导入或受认证的同步服务实现，具体取舍留在后续手机阶段。

## 产品完成标准

第一道题从空中文素材到正式答案能走通；第二道相关题能接收用户选择的真实素材并重新组织。双语素材事实等值，答案素材颜色可追溯到实际采用的素材，英文分类和用法提示支持英语学习界面。失败结果保留重写机会，不产生伪答案。Task 1 不创建素材，Task 2 与口语不跨库推送。文件题库批次有溯源、不重复、不虚构缺失题图。结果导入不能篡改其他题、跨域污染或使用未知 ID。同一道题再次处理保持唯一当前答案。单词可从两个板块加入并统一乱序复习。上述流程在本地刷新和重启后仍可继续。
