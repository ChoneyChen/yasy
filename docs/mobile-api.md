# iPhone 全量查看接口 · v1

手机端的预定角色是查看全部题目、答案、素材、语料、单词和复习记录。Mac 负责素材书写、AI 处理和主数据库。首版已实现响应式界面及稳定的只读数据合同；手机与 Mac 之间的认证、配对和连接尚未实现。服务当前只监听 `127.0.0.1`，不会因为预留手机接口而向局域网开放。

## 已实现的只读接口

| 接口 | 返回内容 |
| --- | --- |
| `GET /api/v1/manifest` | 协议版本、手机角色、资料库范围、只读端点和连接状态 |
| `GET /api/v1/snapshot` | 完整 state、历史答案、背诵状态与记录、文件导入任务 |
| `GET /api/v1/content/{questionId}` | 一道题、当前答案、草稿、双语素材、英文语料及相关推荐 |
| `GET /api/sources/{sourceId}/file` | 当前 Mac 的正式来源 PDF；本次两份原件位于 .local/source-pdfs |
| `GET /api/batches/{batchId}/file` | 当前 Mac 的后续上传资料；位于 .local/uploads，不存在时明确返回 404 |

当前正式活动题库为 743 条、132 个主题、2 个用户 PDF 来源，Task 1 暂为空；快照另保留归档题和历史学习内容。数量与原文收录边界见 [题库来源](question-sources.md)。

这些 `v1` 路径不接受写入。配对上线之后，可以使用经过认证的通道传输同一份 JSON，无须让手机猜测数据库结构。全量快照用于首轮拉取；`id` 与 `updatedAt` 可作为后续增量拉取和缓存的基础。后续身份层须鉴权每个请求，而不只是首次拉取。

## 展示合同

- `scope` 始终为 `speaking`、`writing-task1` 或 `writing-task2`。手机可统一浏览单词，但不能混合素材/语料库。
- iiiapi 自动处理和网页桥都在 Mac 生成、校验和保存。手机合同不会触发生成，快照与内容接口不包含 API 密钥；.local/api-secrets.json 不通过手机接口或备份传输。
- `Answer.textEn` 是完整英文答案。全端共用相同标注数据，背书页与题目页不各自维护答案副本。
- `Answer.materialSpans` 中的 `start` / `end` 是 **UTF-16 字符索引，0 起点、end 不包含在片段内**；`materialId` 指向双语素材。渲染时还应校验边界及 ID，避免缓存版本不一致。
- 按 `Answer.materialIds` 的顺序，素材底色依次为黄、蓝、绿；多于三个时循环，明确保留各素材 ID。表达可与素材底色重叠，用红色波浪下划线标记。
- 表达 `textEn` 必须来自英文答案，材料和语料详情由点击进入。口语/作文答案和语料正文全英文，素材保留 `summaryEn/detailEn` 与 `summaryZh/detailZh` 二元组。
- 手机单击打开对应素材或语料，长按英文单词打开收藏操作。网页已有长按处理器；真正的原生手势与手机端写入权限在配对阶段实现。只读手机默认不修改 Mac 学习记录。

归档题可通过内容接口读取已有答案、草稿与标注；不能因此在手机端获得新建答案权限。原始 PDF 不包含在 JSON 快照中，下载仍需相应 Mac 文件和未来认证通道。

## 下一阶段的连接边界

配对认证、令牌撤销、Mac 休眠/断线提示、缓存与更新策略、原文件下载鉴权都属于手机接入阶段。不能把 loopback URL 直接当成 iPhone 可访问的地址。若采用手机阅读缓存，须保留 schemaVersion、内容更新时间和来源信息；旧版无双语或标注字段的记录应显示“待重新整理”，不能伪造英文翻译或关联。
